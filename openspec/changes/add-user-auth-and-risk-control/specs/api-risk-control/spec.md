## **新增的需求**

### **需求：敏感认证端点须进行速率限制**

系统应使用与操作风险相称的维度对敏感认证端点应用速率限制。

#### **场景：发送验证码使用多维度速率限制**

- **当** 客户端请求电子邮件验证码时
- **那么** 系统应在发送验证码前，至少评估源IP、目标标识符和组合的源-目标上下文的速率限制

#### **场景：登录使用账户和来源限制**

- **当** 客户端尝试登录时
- **那么** 系统应评估速率限制和失败计数器，至少包括源IP、账户标识符和组合的源-账户上下文

### **需求：登录风险应逐步升级**

系统应在失败尝试累积时逐步升级登录保护，而不是对所有失败采用单一的固定响应。

#### **场景：登录升级至验证码验证**

- **当** 源或账户的登录失败次数超过配置的验证码阈值时
- **那么** 系统要求提供验证码或等效证明，然后才允许再次尝试登录

#### **场景：登录升级至临时限制**

- **当** 在验证码升级后仍继续失败登录尝试，或超过更高的阈值时
- **那么** 系统应暂时限制受影响账户、来源或组合上下文的登录尝试

### **需求：刷新令牌重放会触发风险处理**

系统应将替换掉的或以其他方式非活跃的刷新令牌的重用视为安全事件，而非常规的验证失败。

#### **场景：重放的刷新令牌被拒绝并记录**

- **当** 客户端提交一个已被同一会话中更新令牌替换掉的刷新令牌时
- **那么** 系统将拒绝该请求，并记录一个安全事件，表明可能存在重放或令牌泄露

### **需求：受保护的写入操作须进行所有权和频率控制**

系统应对经过身份验证的写入操作（如地址更改和文件上传）应用所有权检查和请求频率控制。

#### **场景：写入请求因缺少所有权而被拒绝**

- **当** 经过身份验证的客户端尝试修改一个不属于该认证用户的资源时
- **那么** 系统将拒绝该请求，并将所有权失败记录为与安全相关的事件

#### **场景：上传请求受文件和频率策略约束**

- **当** 经过身份验证的客户端上传文件时
- **那么** 系统将在接受上传前，强制执行文件类型或大小限制以及请求频率限制

### **需求：最小化公开错误信息披露**

系统应将精确的安全原因保留在内部，同时对外暴露一组更小、稳定的客户端可见认证和风险结果。

#### **场景：无效凭证的原因在内部保持区分**

- **当** 登录失败是因为账户不存在或密码不匹配时
- **那么** 系统保留确切的内部原因，同时返回相同的客户端可见的“凭证无效”结果

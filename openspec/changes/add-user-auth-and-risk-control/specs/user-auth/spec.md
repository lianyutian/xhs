## **新增的需求**

### **需求：邮箱账户注册**

系统应允许客户端使用邮箱地址、密码以及为 `REGISTER` 目的颁发的有效邮箱验证码来创建用户账户。

#### **场景：使用有效验证码完成注册**

- **当** 客户端提交一个未使用、未过期的注册验证码，同时附带有效的邮箱和密码时
- **那么** 系统将为该邮箱创建一个新账户，并将验证码标记为已使用

#### **场景：当验证码无效时注册失败**

- **当** 客户端提交的验证码已过期、被替换、被冻结、已使用，或未为指定邮箱和 `REGISTER` 目的颁发时
- **那么** 系统将拒绝注册，并且不会创建账户

### **需求：邮箱密码登录创建会话**

系统应使用邮箱和密码对用户进行身份验证，并在验证成功时创建服务器跟踪的登录会话。

#### **场景：登录成功并返回基于会话的令牌**

- **当** 客户端为一个活跃且未被锁定的账户提交有效的邮箱和密码时
- **那么** 系统将创建一个活跃会话，颁发一个访问令牌，并颁发一个与该会话关联的活跃刷新令牌

#### **场景：登录失败时不暴露账户是否存在**

- **当** 客户端提交一个未知的邮箱地址或错误的密码时
- **那么** 系统将以相同的客户端可见的“凭证无效”结果拒绝请求

### **需求：刷新令牌轮换**

系统应轮换刷新令牌，使得只要会话处于活动状态，一个刷新令牌只能成功使用一次。

#### **场景：刷新操作轮换令牌**

- **当** 客户端提交一个属于活跃会话的活跃刷新令牌时
- **那么** 系统将提交的刷新令牌标记为已替换，颁发一个新的刷新令牌，并返回一个新的访问令牌

#### **场景：对于非活跃令牌或会话，刷新失败**

- **当** 客户端提交的刷新令牌已过期、被替换、被撤销、被泄露，或与非活跃会话关联时
- **那么** 系统将拒绝请求，并且不会颁发新令牌

### **需求：登出废除会话续期能力**

当客户端从已认证的会话中登出时，系统应废除该会话的续期能力。

#### **场景：登出废除当前会话**

- **当** 一个已认证的客户端从一个活跃会话中登出时
- **那么** 系统将该会话标记为已撤销，并废除与该会话关联的活跃刷新令牌

### **需求：当前用户检索使用认证上下文**

系统应从已认证的访问令牌上下文中解析当前用户，而不是从客户端提供的用户标识符中解析。

#### **场景：从令牌上下文返回当前用户**

- **当** 客户端使用有效的访问令牌调用当前用户端点时
- **那么** 系统将返回该令牌所代表的已认证用户的账户/资料数据

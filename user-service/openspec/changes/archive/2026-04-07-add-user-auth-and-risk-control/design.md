## **上下文**

该仓库目前是一个空的 Maven Java 项目，没有任何应用程序模块、持久层或认证基础设施。此项变更是为计划中的用户服务建立第一个关键安全基础：基于邮箱的注册和登录、基于会话的 JWT 认证、验证码工作流和 API 风险控制。该设计必须保持公共 API 行为的稳定性，同时保留精确的内部安全语义，因为注册、登录、刷新、注销和发送验证码都是高风险入口。

## **目标 / 非目标**

**目标：**

- 定义一个围绕账户、会话、刷新令牌、验证码和安全事件领域对象构建的一致认证架构。
- 支持邮箱注册、邮箱/密码登录、注销、当前用户查询和刷新令牌轮换。
- 为图像验证码和邮箱验证码定义验证码生命周期规则，包括替换、过期、尝试计数和一次性消耗。
- 为验证码发送、登录、刷新、上传和其他敏感用户服务入口点定义 API 风险控制规则。
- 标准化外部错误披露，使客户端获得稳定的下一步指导，同时内部系统保留确切的安全原因。

**非目标：**

- 在此变更中实现短信登录、第三方登录或密码重置。
- 定义网关、WAF 或组织范围的安全基础设施。
- 引入除验证码和邮箱验证之外的完整多因素认证。
- 涵盖用户资料编辑、地址增删改查或 OSS 上传的业务行为，除非涉及其风险控制接触点。

## **决策**

### **基于会话的 JWT 认证**

使用短期访问令牌加上服务器跟踪的刷新令牌，而不是纯无状态 JWT 认证。

- **原因：** 注销、令牌轮换、重放检测和未来的设备/会话管理都需要服务器端的会话真实状态。
- **考虑过的备选方案：**
  - 纯无状态 JWT：更简单，但在吊销和处理重放方面较弱。
  - 仅使用不透明访问令牌：控制力强，但对于初始服务而言，每次请求的开销过大。

### **独立的认证领域对象**

将 `user_account`（用户账户）、`user_session`（用户会话）、`user_refresh_token`（用户刷新令牌）、`verification_code`（验证码）和 `security_event`（安全事件）建模为独立的对象。

- **原因：** 账户身份、会话生命周期、令牌轮换、验证码消耗和安全审计是不同的关注点，有不同的持久性和保留需求。
- **考虑过的备选方案：**
  - 单一用户表加上 Redis 标志：启动快，但将持久身份与短期风险状态混合，难以推理。

### **将验证码视为生命周期对象**

将验证码视为具有 `purpose`（目的）、`target`（目标）、`status`（状态）、过期时间、尝试次数限制和一次性消耗的有状态对象。

- **原因：** 注册和后续的密码重置流程需要明确的替换、过期和审计语义。
- **考虑过的备选方案：**
  - 简单的 Redis `target -> code`（目标 -> 验证码）映射：更简单，但在目的隔离、重试、替换跟踪和审计方面较弱。

### **混合持久化策略**

在数据库中存储持久的认证/安全事实，在 Redis 中存储短期窗口计数器/证明。

- **原因：** 速率限制、验证码挑战和短期窗口失败计数器变化频繁且由 TTL 驱动；会话吊销、令牌轮换、验证码消耗和账户锁定必须保持可解释和可查询。
- **考虑过的备选方案：**
  - 仅使用数据库：对于热点计数器和短期证明太重。
  - 仅使用 Redis：不利于持久安全事实和事后分析。

### **分层错误披露**

维护三层错误含义：确切的内部原因、稳定的面向客户端的业务代码和最少的面向用户文本。

- **原因：** 认证和风险控制端点必须避免帮助攻击者枚举账户或推断内部规则阈值。
- **考虑过的备选方案：**
  - 对客户端完全透明：调试更容易，但会泄露账户存在与否和控制平面行为。

## **风险 / 权衡**

- **[刷新并发性]** 针对同一令牌的并发刷新请求可能导致会话状态分裂。→ 使用条件状态转换，确保只有 `ACTIVE`（活跃）的刷新令牌才能变为 `REPLACED`（已替换）一次。
- **[验证码发送部分失败]** 验证码创建和邮件投递无法包装在单个数据库事务中。→ 持久化一个明确的中间状态，并在提供商调用后更新为 `SENT`（已发送）或 `FAILED`（失败）。
- **[过于激进的锁定]** 简单的基于邮箱的锁定可能让攻击者可以骚扰真实用户。→ 结合 IP、账户和 IP+账户控制，并保持锁定时长较短且在内部可解释。
- **[错误过度暴露]** 精确的客户端消息可能帮助攻击者枚举账户或风险阈值。→ 将高风险认证失败归并为更少的公开结果。
- **[范围蔓延]** 地址增删改查、上传和资料功能可能将认证变更拖入完整的用户服务构建中。→ 将此变更范围限制在认证、验证、会话和风险控制基础上。

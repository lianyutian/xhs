## **原因**

该仓库目前没有任何应用程序代码，但计划中的用户服务从第一天起就需要一个生产级的认证和风险控制基础。如果将注册、登录、令牌刷新、验证码和反滥用保护分开设计或稍后添加，该服务将积累安全漏洞和不一致的行为，而这些在后期修正的成本高昂。

## **变更内容**

- 添加一个以邮箱注册、邮箱/密码登录、当前用户查询、注销以及 JWT + 刷新令牌会话管理为中心的用户认证功能。
- 添加一个覆盖图像验证码、邮箱验证码颁发、验证码生命周期、消耗规则和目的隔离的验证码功能。
- 添加一个针对登录、验证码发送、令牌刷新和其他敏感入口点的 API 风险控制功能。
- 定义会话、刷新令牌、验证码和安全事件的领域对象及其生命周期状态。
- 标准化外部 API 错误语义，使客户端收到稳定、最小化的披露，同时内部系统保留精确的安全原因。

## **功能**

### **新增功能**

- `user-auth`：基于邮箱的账户注册、登录、注销、会话颁发、刷新令牌轮换和当前用户检索。
- `verification-code`：图像验证码和邮箱验证码的颁发、验证、过期、替换和消耗语义。
- `api-risk-control`：针对敏感认证流程的速率限制、验证码升级、临时账户限制、重放检测和安全事件记录。

### **修改的功能**

- 无。

## **影响**

- 在用户/认证层面引入新的 HTTP API。
- 需要为账户、会话、刷新令牌、验证码和安全事件建立数据模型。
- 需要 Redis 支持的短期风险计数器和验证码/证明存储。
- 增加了验证码生成和邮件投递的外部集成，并为未来扩展 SMS 提供了接入点。
